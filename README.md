# 自动梁文谷执行开关

> DSH 峰谷执行开关：高峰时段发送的任务不会立即执行，而是自动挂载为自动化任务，在最近的**谷时**于**当前会话**内执行。

仓库名 `dsh-auto-liangwengu-switch`，插件显示名「自动梁文谷执行开关」；输入框里的开关标签是「峰谷执行」。

## 为什么

DeepSeek API 现行峰谷定价：

| 时段 | 定义（北京时间） | 价格 |
|---|---|---|
| 高峰 | 周一至周五 **09:00–12:00、14:00–18:00**，不含中国法定节假日 | 标准价 |
| 谷时 | 其余全部时间：12:00–14:00、夜间、周末、法定节假日全天 | 标准价 50% |

高峰时段想起一件事，又不想等到晚上再发？打开「峰谷执行」开关发送任务，插件会把它挂成自动化任务，到最近的谷时（当前高峰结束的 12:00 或 18:00）自动送进**当前会话**执行，省一半钱。

调休上班的周末仍按周末识别，恒为谷时。

## 安装

需要 DSH（DeepSeek Harness）0.2.2 系列；本插件实测于 `0.2.2-rc.3` 桌面版。

1. 克隆本仓库到本地任意目录。
2. 在 DSH 的插件管理页选择 **添加插件（本地目录）**，指向仓库根目录；或让 agent 执行 `plugin_manager` 的 `install_bundle`，目标为仓库根目录绝对路径。
3. 刷新 Web 界面，输入框右下、模型选择器右侧会出现「峰谷执行」开关。

## 使用

1. 高峰时段打开「峰谷执行」→ 输入任务 → 发送：消息不立即执行，输入框被清空，开关上方提示「已转为自动化任务：将于今天 12:00/18:00 执行」。
2. 「自动化任务」页会出现对应任务，目标就是当前会话；到点由 DSH Schedule 送进该会话执行（不新建会话）。
3. 当前已在谷时：开关自动关闭且无法打开，点击提示「当前已处于峰谷时段了」——此时直接发送本来就在谷时。
4. 开关按会话记忆（浏览器 localStorage），进入谷时会被自动关闭。

## 行为细节与限制

- 挂载的是一次性计划任务（`at` 定时）；连续发送多条会各挂一个任务，但都排在同一个谷时开始时刻。
- 消息在送达前不进入会话历史、不触发模型请求，会话里不会留下这条用户消息的痕迹，以「自动化任务」页为准；若提示「未转为自动化任务：消息已直接执行」，说明计划任务创建失败，消息按普通消息立即执行（不会丢失）。
- 带图片/文件附件的消息无法用计划任务复现附件，因此仍会立即执行，并在提示中说明。
- 含 `@` 引用 chip 的草稿受支持（关闭开关时保留引用）；含选区引用（quote）的草稿在关闭开关时会退化为普通文本（内容保留）。
- 以 `/` 开头的命令草稿不适用：点击开关会提示「峰谷执行只对普通消息生效」。
- 子会话（右侧栏子智能体）不显示该开关，因为计划任务不能投递到委派子会话。
- 若部署没有可用的 Schedule 服务或 Web 路由，消息会立即执行、前端用离线回退表，均不会丢内容。
- 时间按浏览器与 Host 各自的本地时钟计算；时区固定北京时区（Asia/Shanghai）。

## 节假日数据与未来年份

节假日数据是单一数据文件 [holiday-data.json](holiday-data.json)（`years → 放假日期区间`），当前收录 2026、2027 年国务院放假安排：

- 2026 年：国办发明电〔2025〕7 号
- 2027 年：国办发明电〔2026〕10 号

未来年份不会失效，有三层兜底：

1. **Host 自动补全**：当前年份不在数据文件里时，Host 从公开数据集 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)（逐日列出国务院放假安排并标注出处）拉取当年 `isOffDay` 日期合并进内存日历，每小时重试；网络不可用或数据不合法时保持原数据。
2. **前端从 Host 取权威日历**：Host 通过只读路由 `GET /peak-valley/calendar` 下发「高峰窗 + 节假日日期 + 覆盖年份」，浏览器启动时采用，因此新增年份只需更新数据，不必改客户端代码。
3. **显式降级**：当前年份仍未被覆盖时按「工作日即高峰」保守工作，极端情况只是节假日当天把任务排到 12:00/18:00（无害延后）；此时开关标签显示 `峰谷执行*`，悬停与开启提示会说明"节假日数据未覆盖 YYYY 年"。

手动固定新一年：在 [holiday-data.json](holiday-data.json) 的 `years` 里追加区间并重载插件即可。如果 DeepSeek 调整的是峰谷**时段规则**（而非节假日），则需要改代码里的 `PEAK_WINDOWS`（Host `time.js` 与 `client.js` 各一处，测试会比对）。

## 实现摘要

- **客户端**（[client.js](client.js)）：占用 DSH 会话级槽位 `conversation.input.activity`（模型选择器与发送按钮之间）。开关打开期间在草稿里维护一段不可见、零宽标记（3 × U+2060 WORD JOINER；`String#trim` 不会删除它，因此能穿过输入框发送时的首尾裁剪）；关闭开关、进入谷时、草稿变空或改为命令草稿时移除，含引用 chip 的草稿通过结构化快照还原。发送后读 Host 计划任务目录核对是否真的挂载，并据此提示。
- **Host**（[index.js](index.js) / [interception.js](interception.js)）：在 `agent/pre-step` 瀑布里识别带标记的用户消息，调用 `schedule.create({ timing: { kind: 'at', at: 当前高峰结束时刻 }, target: { kind: 'session', sessionId } })` 创建一次性任务，并把该消息从本步移除（不产生模型请求、不写会话历史）；创建失败或当前已在谷时时回退为立即执行并剥掉标记。只读路由下发前端日历。
- **日历**（[time.js](time.js) / [holidays.js](holidays.js) / [holiday-sync.js](holiday-sync.js) / [calendar-payload.js](calendar-payload.js)）：单一权威来源在 Host；客户端只在路由不可用时使用内置 2026–2027 离线回退表。

## 开发与测试

测试不依赖 DSH 运行中的进程，也不需要联网（远程补全用注入的假 fetch；另有一个可选的 `test/remote-live.mjs` 联网实测脚本）：

```sh
node test/test.mjs
node test/client-sync.mjs
node test/client-smoke.mjs
node test/bundle-check.mjs
```

或 `npm test`。覆盖：时段边界（09:00/12:00/14:00/18:00）、周末与调休周末恒谷时、法定节假日工作日、下一谷时计算、节假日文件校验、远程数据补全成功/失败路径、客户端 payload 契约、不可见标记穿过发送裁剪、Host 拦截与计划任务参数（高峰→12:00/18:00；谷时立即执行；失败回退；附件/命令/标记-only 边界）、客户端与 Host 日历在 2026–2028 的 8768 个时刻逐点一致，以及未覆盖年份的提示。
